# graph-special[408] · 规格（v2 · 方案验收版）

> 这份文档是**规格**，不是施工委托。
> v1 的问题：把「设计判断」写成了「用户需求」（已定表里混进方法项），并用「先给默认值，别写死」把规则推给实现者 —— 实现者只能猜，猜错就产生下一份错文档。
> v2 的原则：**规则必须裁决，内容允许留白。**

---

## 零、这个项目是什么

一个**逼自己把六科因果关系讲通**的脚手架。图是副产品，讲不通才是失败信号。

- 主要代码由 harness 写；用户负责**内容对错与理论**。
- 不是题库、不是笔记库、不是教材搬运、不是给别人看的产品。

### 内容验收（唯一硬标准）

> 给任意一节，90 秒内说清：
> **① 它要解决的是上一节的哪个缺陷？ ② 如果它不存在，会发生什么？**
>
> 说不出来 = 这条链是编的，不是理解的。

这条验收不看渲染、不看美观、不看节点数。

## 一、范围

**三个顶级域，不是两个，不是四个：**

```
408        → 操作系统 / 数据结构 / 计算机组成原理 / 计算机网络
数学        → 高等数学 / 线性代数 / 概率论与数理统计
政治        → 马原 / 毛中特 / 史纲 / 思修与法基
```

- 骨架服从**目的**（考研），所以按大纲章 → 节组织。
- 数学、政治**必须**在图上（v1 的「不进这张图」是错的）。
- 不复用 `knowledge-graph-3d` 的**内容**：`computer/*`（AI / dsa / languages）里是空壳与无关内容，`foundation`（数学）是 AI 视角而非考研视角，全部推平。
- **复用**的只有渲染房架：`CameraController.js` / `Graph3D.js` / `InfoPanel.js` / `SearchUI.js` / `main.js` + `public/css/common.css`。

## 二、三层模型（v1 把它压成了「一条主线」，这是根本歧义）

| 层 | 回答什么 | 存在形式 | 服从谁 |
|---|---|---|---|
| **骨架** | 考什么、怎么分类 | `children` 树（大纲章→节） | 服从目的：按考研大纲 |
| **因果内容** | 为什么需要它、它带来了什么新问题 | 节点 `content.chain` + 节点间 `relations` 边 | 服从理解：按各科自己的逻辑 |
| **旁支** | 它真在哪用 / 更深一层在哪 | `ext-*` 节点，挂在科根下，回连到被扩展的节 | 服从理解：按应用走 |

**为什么必须分三层**：骨架若也承担叙事，大纲会压死理解（v1 就是这么写的：「按节」+「问题→方案→新问题」写进同一张已定表）；反过来，若旁支挂到节下面，骨架树就不再等于大纲，以后**按大纲查漏**就做不到了。

### 三科各填哪几层

| 科目 | 骨架 | 因果内容 | 旁支 |
|---|---|---|---|
| 408 | 大纲章→节 | **演进链**：上一节缺陷 → 本节方案 → 引入的新问题 | 真实系统 / 工程现象 |
| 数学 | 大纲章→节 | **逻辑必然**：为什么必须有这个概念（不是历史演进） | AI 应用（《鸢尾花书》那条线，后续可增改） |
| 政治 | 大纲章→节 | **关系网**：概念之间的隶属 / 对立 / 发展（不追「为什么需要」） | 现实现象（可选，暂不做） |

> 政治是压力测试：它是**关系网**而非演进链，说明「主线」不是全局唯一的，而是分科的。这层照实写，不硬套。

## 三、粒度（是默认值，不是铁律）

- **默认：节。**
- 一节能被一个问题干净驱动的（虚存：内存不够 → 分页 → 缺页 → 抖动），直接成链。
- 一节塞了多个不相关问题的（文件系统实现 = 目录结构 + 空闲空间管理 + 磁盘布局），**允许该节下挂多个问题子节点**，各自有独立的第一性问题。禁止把不相关的问题硬拉成一条链 —— 那是假因果。
- 旁支节点不参与「节」的计数。

```js
      problem:      '物理内存装不下所有进程，且进程间不能互相踩',
      solution:     '分页 + 页表 + 缺页中断，把"用不到"的页放到磁盘',

```

### 边

```js
relations: [
  // 因果链：从「上一节」指向「本节」，label 必须能当一句话读
  { source: '408-os-mem-分页', target: '408-os-mem-virtual', label: '内存不够→虚存', color: '#ff9f43' },

  // 旁支：从节指向 ext 节点

```

约束：`label` 必须能在不看节点详情的情况下读懂因果；写不出这句话，说明这条链没想清楚，**不要建这条边**。

## 五、跨科连线

- **暂不做**，但 id 规则已为此留好（第四节的 `408-` / `math-` / `pol-` 前缀）。
- 理由是：跨科连线（Cache ↔ 虚存、TLB ↔ 页表 ↔ Cache）是这类图最值钱的部分，但它要求两端都先讲得通。先做单科，连线自然浮现。

---

## 六、MVP（只验一件事：这条链站不站得住）

1. 顶层骨架一次定死（三个顶级域 + 四科/六块），不返工。
2. **只做一科、一条链**：建议 OS 的「内存管理」段（内存不够 → 虚存 → 缺页 → 置换 → 抖动）。
3. 每个节点必须填满 `content.chain` 三段；填不满的节点**不建**。
4. `npm run dev` 一条命令能预览；点节点出面板，边上能看到链的走向。

不做：跨科连线、四科齐全、政治与数学的内容、复习状态标记、3D/2D 之争。
