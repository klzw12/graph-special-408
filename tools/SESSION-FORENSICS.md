# 🔎 会话 / 工作区数据丢失排查清单

> 来源：DSH issue #9615 实测复现。症状：改名工作区目录后
> `workspaceController is unavailable`、全服务链 pending、历史会话“不见了”。
>
> 结论先给：**数据几乎不会真的丢，丢的是“归属记录”和“路径的一致性”。**
> 所以第一步永远不是修文件，是判断**三层里哪一层失配**。

---

## 0. 先记四条底层事实（不懂原理会修错方向）

| 事实 | 后果 |
|---|---|
| 会话文件是 **zstd 压缩 + 多帧拼接**（一帧一条记录） | 编辑器打开是乱码，`grep` 搜路径可能搜不到 |
| 第 1 帧是 **header**（记着 `cwd`），后面每批一次追加一帧 | 只解第 1 帧就够；只重压第 1 帧就够 |
| 帧头有 **checksum 开关**（1 比特）+ 帧尾有**值**（4 字节） | 开关是写端决定的固定值；值随数据变。别把开关当值 |
| 写端 **只给 header 帧带 checksum**，数据帧不带 | 重压时必须**逐帧沿用原参数**，不能统一用默认 |

---

## 1. 三层状态：改错层 = 症状不变

| 层 | 位置 | 什么时候坏 |
|---|---|---|
| **名册层** | `~/.dsh/storages/workspace.json` → `tables.workspaces[*].sessionIds` | `mutate()` 用启动时的一次性路径缓存裁剪，**cwd 一时解析不出就被永久删除** |
| **数据流层** | `~/.dsh/sessions/<编码后的路径>/<session-id>/session.v4.jsonl.zstd` 第 1 帧 `cwd` | 目录改名/移动/盘未挂载 |
| **派生层** | 目录名 `--C-Users-...--` | 由 cwd 算出，必须跟着变 |

目录名编码规则（实测精确复现）：ASCII 原样、`:` 和 `\` 压成一个 `-`、非 ASCII 转 `~`+UTF-16 码元、首尾各补 `--`。
例：`C:\Users\31783\Desktop\graph-special-408` → `--C-Users-31783-Desktop-graph-special-408--`；`はな` → `~306F~306A`。

## 2. 四步排查

### S1 症状归层：先问“谁在等谁”
`workspaceController is unavailable` + 全链 pending = 依赖链最底层挂了，**不是 UI 问题**。从被依赖最底层往上查，不要从报错最响的地方开始。

### S2 取证，不要猜

```powershell
# 帧结构体检（帧数 / 帧头参数 / header 是否恰好一行）
node tools/frame-inspect.mjs "<session.v4.jsonl.zstd>"
```

看三样：
- **帧数**（数百级为正常，1 帧=被整解整压过）
- **帧 0 参数**（checksum / singleSeg / csFlag，重压时的对照基准）
- **header 行数“恰好一行”**

### S3 只改最小单元

- 需要改的**只有第 1 帧的 `cwd`**。历史记录里出现的旧路径是无害文本，**不要**去改（多改一次多一次风险）。
- 重压必须**沿用原帧参数**；node 的 `ZSTD_c_checksumFlag` 等高层参数不完全可控（实测 `checksum=0 + contentSizeFlag=1` 仍会输出 checksum=1），**做不到就报错退出，不许静默降级**。
- 其余帧**逐字节原样拼接**。

### S4 清名册层（否则文件修好也不会自动回组）

`bootstrap` 只在**首次初始化**时对账，`initialized: true` 之后重启**不会**把会话重新挂回工作区。

```powershell
# 编辑 ~/.dsh/storages/workspace.json，把 session id 加回对应工作区的 sessionIds
```

先停 DSH，改完再启动。

## 3. 现象 → 结论 对照表

| 现象 | 结论 | 下一步 |
|---|---|---|
| 编辑器打开是乱码 | 正常，是压缩 | 不要“另存为文本” |
| 压缩流里搜不到路径 | **不代表内容不在** | 解压第 1 帧确认 |
| 修好文件、重启后会话仍不在列表 | 名册层没对账 | 手工补 `sessionIds` |
| 修完整个列表变空 / 会话静默消失 | 帧被整解整压 → 读端 `SessionPersistenceCorruptionError` → catch → **静默跳过** | 回滚，用逐帧方案重做 |
| 帧数变成 1 | 被整解整压过 | 同上 |
| 帧 0 参数与其它文件不一致 | 重压时参数漂移 | 按原帧参数重压，或改用 zstd CLI |

---

## 4. 三类常见误判（本课重点）

| 误判 | 真相 |
|---|---|
| 搜不到 = 内容不在 | 内容在，只是换了个存法（压缩） |
| 帧头 `checksum: 1` 是校验和的值 | 那是**开关**，值在帧尾 4 字节，随数据变 |
| 数一数就知道字符数 | 字符 ≠ 字节；反斜杠在文件里是两个字符；末尾换行看不见 |

**共同点：把“我以为的量”当成“实际的量”。所有结论必须落到一次可复现的实测。**

---

## 5. 预防

- 工作区目录**尽量不改名/不移动**；必须改，就同时改三处：目录名、会话 header 的 `cwd`、`workspace.json` 的 `path`。
- 改之前**备份** `~/.dsh/sessions/` 与 `storages/workspace.json`。
- 网络盘 / 可移动卷上的工作区风险最高（启动时路径解析失败就会被裁剪）。
